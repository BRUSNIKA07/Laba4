Оборона Бункера: Постапокалипсис (Last Outpost)
Распределение ролей и сетевая архитектура
Описание проекта
Выжившие защищают вход в подземное убежище от волн мутантов. Днём — строительство и разведка, ночью — оборона.
•Соло: одиночная игра на своём компьютере.
•Мультиплеер по локальной сети: до четырёх игроков. Один игрок создаёт игру в клиенте (он становится хостом), остальные подключаются к нему.
•Рейтинг: выживание на бесконечных ночах. В топе отображаются состав отряда и день, до которого отряд дожил.
Сетевая архитектура
•Хост запускает игровой сервер внутри своего Electron-приложения. Сервер слушает порт в локальной сети.
•Все игроки, включая хоста, подключаются к серверу хоста по IP-адресу и порту. Интернет не нужен.
•PostgreSQL установлен на компьютере хоста. Клиенты к базе напрямую не подключаются, все запросы идут через сервер хоста.
•В лобби хост видит свой локальный IP и порт и передаёт их остальным игрокам.
•Если хост закрывает игру, сессия завершается для всех.
Стек
•Клиент и хост: Electron, Vue 3, Pinia, HTML5 Canvas или PixiJS (ночная фаза).
•Сервер внутри Electron: Node.js, Fastify или NestJS, Socket.io или Colyseus.
•База данных: PostgreSQL на машине хоста, Prisma ORM.
•Общий код: монорепозиторий (client, server, shared), TypeScript.

План первой недели
Дни 1–2:
•Архитектор: инициализация монорепозитория, базовые типы в shared/.
•Frontend: верстка экранов входа, меню «Создать игру» и «Подключиться».
•Backend: поднятие PostgreSQL, схема Prisma, API логина и пароля.
•Electron: каркас Electron и Vue, настройка safeStorage, проверка PostgreSQL.
Дни 3–4:
•Архитектор: отрисовка сетки бункера, спавн врагов, стрельба турелей.
•Frontend: верстка дневной фазы и лобби хоста.
•Backend: сервер хоста с подключением клиентов по IP и порту, чат лобби.
•Electron: запуск сервера в процессе хоста, показ IP и порта, таблица баланса.
Дни 5–7:
•Архитектор: интеграция ночного боя с сетевыми событиями.
•Frontend: подключение Pinia к API рейтинга и сокетам.
•Backend: синхронизация фаз день и ночь, запись рекордов в PostgreSQL хоста.
•Electron: тест четырёх клиентов в одной сети, инструкция по открытию порта в файрволе.
Цели первой недели
К концу седьмого дня хост должен создавать игру в приложении, а три других компьютера в той же сети должны к ней подключаться.
•Монорепозиторий собирается без ошибок.
•Регистрация и вход работают через API с JWT.
•Хост создаёт игру, остальные подключаются по IP и порту.
•Ночная сетка отрисовывается, турели стреляют, мутанты идут по пути A*.
•Результат матча сохраняется в PostgreSQL на машине хоста.
Договорённости по работе
Предлагаемые правила, их нужно утвердить на первом созвоне.
•Общий репозиторий, у каждой роли своя ветка с префиксом по имени.
•Типы в shared/ меняет только архитектор. Остальные предлагают изменения через pull request.
•Код-ревью обязателен для server/ и shared/, там логика боя, сети и рейтинга.
•Короткий ежедневный синк на 15 минут.
•Баланс хранится отдельно от кода, правки баланса не требуют пересборки клиента.
Риски и открытые вопросы
•Хост является единой точкой отказа: если он выходит, сессия завершается для всех. Снижение риска: понятное сообщение игрокам и сохранение прогресса матча.
•Рейтинг хранится в PostgreSQL на машине хоста. Нужно решить, где лежит история, если хост меняется.
•Установка PostgreSQL на каждом компьютере хоста неудобна для игроков. Нужно решить: требовать установку вручную или использовать встроенную базу.
•Файрвол Windows может блокировать входящие подключения. Снижение риска: инструкция и проверка порта при запуске хоста.
•Накрутка рейтинга. Снижение риска: серверная валидация логов матча.
•Нужно выбрать фреймворк сервера (Fastify или NestJS), библиотеку сокетов (Socket.io или Colyseus) и рендер (Canvas или PixiJS) до дня 3.
Критерии готовности первой недели
•Все четыре роли делают pull request в общую ветку разработки.
•Три клиента подключаются к хосту в одной локальной сети и видят одну фазу дня.
•Запись рекорда попадает в PostgreSQL хоста и появляется в таблице рейтинга.
•Сборка Electron запускается минимум на одной платформе.
•Баланс турелей и волн читается из конфигурации без правок кода.
